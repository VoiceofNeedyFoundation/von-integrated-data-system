# Phase 1 roadmap

Stages 1–3 establish the evidence for architecture and migration. Frontend coordination and test planning begin during discovery. Backend changes, deployment and historical migration depend on the applicable review and approval. Current activity is limited to the Voice of Needy GitHub repository.

| Milestone and objective | Required inputs and dependencies | Codex responsibilities and deliverable | Analyst role and approval | Verification |
| --- | --- | --- | --- | --- |
| 1. Organisational discovery | Reviewed project guidance, programme documents and meeting evidence | Maintain the evidence register, project understanding, requirements and open decisions. | Correct and approve workflow scope at Checkpoint 1. | Every confirmed rule points to evidence or a recorded analyst decision. |
| 2. Source inventory | Supplied project folders and discovered references | Maintain machine-readable file and worksheet inventories; resolve shortcuts and authority classes. | Confirm authoritative sources and historical coverage. | Folder coverage reconciles to the inventory; derived and duplicate versions are labelled. |
| 3. Profiling and lineage | Authorised sources and approved authority hierarchy | Profile missingness, duplicates, validity, category variation and conflicts; draft field-level lineage and exception queues. | Review quality issues and mappings at Checkpoint 2. | Results reproduce from unchanged sources and reconcile counts by source. |
| 4. Conceptual modelling | Approved workflow scope and reviewed source evidence | Draft entities, relationships, identifier strategy, validation rules and lifecycle states. | Validate business rules, optional paths and identity-review criteria. | Model supports incomplete histories and repeat events without duplicating person identity. |
| 5. Model review | Draft model, mappings and examples | Record decisions and create the approved baseline. | Approve the canonical model at Checkpoint 3. | Approval covers identifiers, cardinalities, missing states, security implications and frontend operations. |
| 6. Backend architecture | Approved model, expanded scope authorisation and environment access | Implement versioned migrations, constraints, indexes, roles, security and audit structures in an approved development environment. | Approve access rules and material security changes. | Database rebuilds from migrations; allowed and denied access pass synthetic tests. |
| 7. Migration pipeline | Approved model, mappings and environment | Build extraction, staging, validation, identity review, load, exception and reconciliation steps. | Approve transformation and matching rules. | Rehearsal runs prove rerun safety, failures, recovery and count accounting. |
| 8. Historical migration | Approved production plan and rehearsal evidence | Execute only the authorised load and record every source disposition. | Approve production execution and material compromises. | Migrated and unresolved records trace back to source; rerun produces no duplicates. |
| 9. Reconciliation | Source, staged, loaded and exception results | Compare counts, aggregates, relationships and completeness. | Accept Checkpoint 4 reconciliation. | Every source record has a disposition and every discrepancy has an explanation or owner. |
| 10. Frontend integration readiness | Priority journeys, approved model and role matrix | Publish versioned operations, examples, errors and compatibility rules. | Validate with the frontend developer; approve breaking changes. | Agreed create, update, read and reporting scenarios pass under expected roles. |
| 11. Testing and QA | Supported workflows and access matrix | Run database, data, security, integration and recovery checks. | Validate analytical acceptance criteria. | Required checks pass and remaining risks are recorded. |
| 12. Release and handover | Accepted reconciliation, QA and release approval | Document setup, operations, monitoring, recovery and VoN ownership. | Coordinate release approval and VoN acceptance. | VoN owners can operate and verify the released system. |
