# Phase 1 roadmap

Stages 1–3 establish the evidence for architecture and migration. Frontend coordination and test planning begin during discovery. Backend changes, deployment and historical migration depend on the applicable review and approval. Current project activity is scoped to the Voice of Needy GitHub repository.

| Milestone and objective | Required inputs and dependencies | Codex responsibilities and deliverable | Analyst role and approval | Verification |
| --- | --- | --- | --- | --- |
| 1. Organisational discovery | Master brief, Goalkeep guide and SOP, VoN process evidence | Inspect infrastructure within scope. Document workflow, requirements, gaps and kickoff project boundaries. | Confirm workflow scope and business priorities at Checkpoint 1. | Every confirmed requirement names its evidence or analyst decision. |
| 2. Source inventory | Accessible source folders and references identified in discovery | Inventory relevant workbooks and tabs, field names, periods, counts, entity candidates and ownership in a machine-readable register. | Confirm authoritative files and coverage. | Compare the register against accessible folder listings and mark coverage gaps. |
| 3. Profiling and lineage | Inventory and authorised source extracts | Profile missingness, duplicate candidates, validity, category variation and cross-source conflicts. Record draft field-level lineage and exceptions. | Review quality issues, proposed mappings and ambiguous rules at Checkpoint 2. | Summaries reproduce from the same inputs. Counts and field references can be traced. |
| 4. Draft modelling | Workflow scope and reviewed source evidence | Draft the ERD, data dictionary, relationships, identifier strategy, validation rules and source-to-target mapping. Draft frontend operations from verified workflows. | Validate business rules, optional relationships and identity review criteria. | Model represents incomplete historical cases and supported operational scenarios. |
| 5. Model review | Draft model, mappings and workflow examples | Record decisions, revise affected artifacts and capture the approved baseline. | Approve the canonical model at Checkpoint 3. | Approval covers identifiers, cardinalities, missing data, exception handling and interface implications. |
| 6. Backend architecture | Approved model, scope authorisation and access requirements | Implement versioned migrations, constraints, indexes, roles, row-level security and audit structures in an approved development environment. | Review access rules and approve material security changes. | Rebuild from migrations. Exercise allowed and denied access with synthetic data. |
| 7. Migration pipeline | Approved model, mappings, source access and development environment | Build extraction, staging, validation, identity review, load and reconciliation. Document lineage, exceptions and reruns. | Approve material transformation and matching rules. Review uncertain identities. | Synthetic and authorised rehearsal runs exercise reruns, failures, recovery and count accounting. |
| 8. Historical migration | Rehearsal results, approved target, migration scope and operational plan | Execute the authorised load, preserve source records and exceptions, and record execution evidence. | Approve production execution and material compromises. | Trace migrated and unresolved records to their source. Repeat run produces no duplicate records. |
| 9. Reconciliation | Source, staged, loaded and exception results | Compare counts, important aggregates, relationships and completeness. Document discrepancy explanations and unresolved issues. | Accept reconciliation at Checkpoint 4. | Each source record has a documented disposition and discrepancies have an owner. |
| 10. Frontend integration readiness | Priority forms, approved model and access contract | Publish versioned interface specifications with examples, errors and compatible changes. Exercise integration workflows with synthetic data. | Validate business scenarios with the frontend developer. Approve breaking changes. | Agreed create, update, read and reporting scenarios pass under expected roles. |
| 11. Testing and QA | Supported workflows, migrations and access matrix | Run database, data, security, integration and recovery checks. Capture results and resolve defects. | Validate analytical acceptance criteria and review remaining issues. | Required checks pass and applicable approvals are recorded. |
| 12. Release and handover | Accepted reconciliation and QA, release approval and VoN ownership | Document setup, operations, monitoring, recovery and handover. Deploy only within approved release scope. | Coordinate release approval and acceptance by VoN owners. | VoN owners can verify access, repeat documented operations and locate the release and recovery evidence. |
